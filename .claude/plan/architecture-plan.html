Section 04

Layered Architecture Diagram

Each layer has a single responsibility. Data flows top-down, and no layer skips the one below it.

🌐 Client (Browser)

HTTP Requests / HTML Responses

🔌 URL Dispatcher

config/urls.py routes to app-level urls. Named URLs with namespaces.

committee:create billing:teacher-bill courses:update

🛡 Middleware

Auth CSRF Session Security Messages

👁 View Layer (Thin)

Parse request via Forms → Call service → Pass context to template → Return response

accounts/views.py committee/views.py courses/views.py thesis/views.py billing/views.py

📋 Form Layer (Validation)

Django Forms & ModelForms handle input validation, type coercion, and error messages.

LoginForm CommitteeForm CourseForm ThesisForm BillSearchForm

⚙ Service Layer (Business Logic)

All complex logic lives here. Views never contain business rules.

committee/services.py billing/services.py billing/rates.py billing/pdf.py

🗃 Model Layer (Data)

Clean models with PascalCase names, snake_case fields, choices for enums, and __str__ on every model.

Faculty External Session Semester Course SemesterRole ThesisPaper

🗃 Database

SQLite (development) → PostgreSQL (production)

def login_view(request):
    form = LoginForm(request.POST or None)
    if form.is_valid():
        user = authenticate(
            username=form.cleaned_data['email'],
            password=form.cleaned_data['password']
        )
        if user:
            login(request, user)
            return redirect('home')
        form.add_error(None, 'Invalid credentials')
    return render(request, 'accounts/login.html', {'form': form})

def validate_committee(chairman, tab1, tab2, session):
    """All committee validation in ONE place."""
    errors = []
    if len({chairman, tab1, tab2}) < 3:
        errors.append("Faculty cannot be selected more than once.")
    if Semester.objects.filter(session=session, chairman=chairman).exists():
        errors.append("Chairman already assigned in this session.")
    return errors

from dataclasses import dataclass
from . import rates

@dataclass
class BillLineItem:
    role: str
    department: str
    course_code: int
    paper_count: int
    duration: int
    amount: int

class BillCalculator:
    """
    SINGLE implementation of bill calculation.
    Used by: teacher_bill view, semester_bill view, PDF export.
    Eliminates 480 lines of duplicated code.
    """
    def __init__(self, session, semester, faculty):
        self.session = session
        self.semester = semester
        self.faculty = faculty
        self.items = []

    def calculate(self):
        self._add_committee_roles()
        self._add_thesis_roles()
        self._add_semester_roles()
        self._add_course_roles()
        return self.items

    def total(self):
        return sum(item.amount for item in self.items)
billing/views.py Python — Thin wrapper (~10 lines per view) 
@login_required
def teacher_bill(request, session_year, sem_id):
    session  = get_object_or_404(Session, year=session_year)
    semester = get_object_or_404(Semester, session=session, sem_id=sem_id)
    faculty  = get_object_or_404(Faculty, user=request.user)

    calculator = BillCalculator(session, semester, faculty)
    items = calculator.calculate()

    return render(request, 'billing/teacher_bill.html', {
        'items': items,
        'total': calculator.total(),
        'faculty': faculty,
        'semester': semester,
    })

Section 09

Phased Migration Strategy

Six incremental phases. Each phase is independently deployable and testable.

1

Phase 1 — Foundation

  • Create proper .gitignore, remove venv from git
  • Split settings into base.py / development.py / production.py
  • Move SECRET_KEY to environment variable
  • Remove all junk imports (tkinter, turtle, pyexpat)
  • Create requirements.txt with pinned versions
  • Fix ROOT_URLCONF to point to config.urls
2

Phase 2 — Extract Apps + Models

  • Create 5 app directories under apps/
  • Refactor models: PascalCase names, snake_case fields
  • Add choices for semester IDs and course types
  • Migrate faculty to Django User + Faculty profile
  • Run makemigrations + migrate
  • Data migration to hash existing plain-text passwords
3

Phase 3 — Forms + Service Layer

  • Create forms.py for each app with ModelForms
  • Extract bill calculation into billing/services.py
  • Extract committee validation into committee/services.py
  • Create billing/rates.py for all rate constants
4

Phase 4 — Views + URLs

  • Rewrite views as thin wrappers calling forms and services
  • Add @login_required to all views
  • Add @chairman_required custom decorator
  • Replace all string-concatenated URLs with reverse()
  • Set up URL namespaces for each app
5

Phase 5 — Templates + Static

  • Create base.html with proper template inheritance
  • Extract all inline CSS into static/css/styles.css
  • Create reusable alert/modal components
  • Namespace all template directories
6

Phase 6 — Tests + Hardening

  • Write tests for BillCalculator (12 rate rules)
  • Write tests for committee validation logic
  • Write tests for authentication flow
  • Add get_object_or_404() everywhere
